# Jarvis high ticket repository

Start with README.md, TECHNICAL-REVIEW.md, skills/README.md and course/studio/data/outline.json. This repo is the shared course/skills source. It includes unfinished instruction drafts and historical test reports, not a completed autonomous agent runtime.

Preserve the student's buyer/problem/offer through every handoff. Keep research, six-line offer creation, marketing, private proposals and accepted delivery scope distinct. Use current funnel order: landing, application, qualified booking, actual booking event, post-booking confirmation, pre-call follow-up.

Read course/studio/VOICE.md and CONVENTIONS.md before editing lessons. No em dashes in canonical student skills. Use short student prompts that reuse saved context. Claims need evidence; demonstrations are not client results. A screening score is a research heuristic, not market validation. No public offer prices; private sales documents may contain pricing.

Never add secrets or private contact/call datasets. Do not expose the studio server publicly. Preserve private repo visibility. This repository does not authorise sends, calls, ad spend or client writes.

After course edits run scripts/build_reading_copy.py and scripts/review_inventory.py --write. Run scripts/review_inventory.py --check before a handoff. Report functional, learner/commercial and visual review separately. Do not claim Base44 or student tests from a local file check. Keep archived and rejected examples labelled.
