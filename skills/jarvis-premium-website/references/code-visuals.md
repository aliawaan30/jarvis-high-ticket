# Code-built visuals (media level 1)

Most premium sites need no generated media. Built in code from the brand's tokens, these visuals are free, instant, sharp at every size, light to load, easy to edit, and never look AI-generated. Use them first; add Higgsfield only when the media level calls for it (image-direction.md).

## The toolkit

1. **Typography as the hero.** Very large display type with the brand's type device (italic emphasis, width contrast or bold capitals), a kinetic reveal, and generous space. Many of the best sites lead with words alone.
2. **Spot illustrations.** Simple line or flat SVG drawings of the niche's objects and moments (a phone, a calendar, a toolbox, a key, a leaf, a tooth), in the brand palette with one consistent stroke width and corner style. Keep them simple; never imitate a known illustration style or character.
3. **Icons.** One consistent set (stroke width, corners, size) for services, steps and features, drawn as SVG or from one open-licence icon library used throughout.
4. **Diagrams.** How it works, before and after, a process flow, a split of responsibilities, a coverage area or a comparison, drawn as SVG. Style rules:
   - Clean and flat like a well-designed print infographic: thin strokes, few colours, real labels in the brand's type. No glow, gradients, neon, floating orbs, robot faces or other generic AI look.
   - The brand mark sits inside the diagram as the central node.
   - Lines trace in and nodes fade in, in sequence, when scrolled into view; pause while off screen.
   - Design each diagram separately for phones (a vertical flow with larger labels), never just shrunk.
   - Every diagram has a text alternative listing the same information.
5. **Subtle backgrounds.** Soft gradient meshes in the palette, a fine film-grain texture, a faint pattern made from the logo mark or a niche shape, gentle animated blobs, or a dotted grid. Always behind content and never fighting the text; contrast still checked.
6. **Live product demos.** For tech and outcome services: phone screens, chat transcripts, call cards, notifications, calendars and dashboards animated in code (see motion-system.md).
7. **A service-area map.** A stylised SVG map of the city with the client's areas highlighted and labelled, drawn from simple shapes (not a copied map image). Areas sit in their real relative positions, north at the top; stylised never means rearranged.
8. **Numbers and charts.** Confirmed figures as large animated numbers; simple bar or line charts drawn in SVG for real data only.
9. **Device frames.** Laptops, browsers and phones drawn in code around real screenshots or code-built interfaces.
10. **Shape and colour blocks.** Bold colour fields, cut corners, arches or circles from the brand's signature shape, used as framing devices for text and real photos.
11. **The client's real photos.** Always first when they are good: crop with care, set focal points, colour-grade gently toward the palette.

## Rules

- One illustration style, one icon set and one background treatment per site.
- Everything uses the colour tokens and follows the surface rules (design-system-rules.md).
- Visuals still pass the relevance test: they show the buyer, the problem, the product working or the result.
- Animate with the motion system's quiet defaults and signature moments; drawings can draw themselves on, numbers count up, demos play.
